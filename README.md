## Notebooks

### Hierarchical RAG

[`HIERARCHICAL_RAG.ipynb`](./HIERARCHICAL_RAG.ipynb) builds a hierarchical-retrieval RAG pipeline over a PDF report, end to end:

1. **Parse** the PDF into structured elements (`unstructured`, `hi_res` strategy — text, tables, images, figure captions).
2. **Enrich** non-text elements — table summaries and image captions (stubbed here; swap in real LLM/vision calls).
3. **Convert** enriched elements into LlamaIndex `Document`s, grouped by page/section.
4. **Chunk** hierarchically with `HierarchicalNodeParser` (parent chunks + smaller leaf chunks, linked by relationship metadata).
5. **Store** leaf-node embeddings in a persistent ChromaDB vector store, while a docstore keeps the full parent/child node tree.
6. **Retrieve** with `AutoMergingRetriever` — search on precise leaf chunks, then automatically merge back up to the parent chunk when enough sibling leaves also match, so the LLM gets fuller context instead of a fragmented chunk.

#### Setup

```bash
pip install -r requirements.txt

# unstructured's hi_res PDF strategy shells out to these binaries:
brew install tesseract poppler   # macOS
# sudo apt install tesseract-ocr poppler-utils   # Debian/Ubuntu
```

Optional: set `HF_TOKEN` to avoid Hugging Face Hub's anonymous rate-limit warning when downloading models (layout detection, embeddings).

#### Notes

- `chroma_db/` and `extracted_images/` are generated by running the notebook and are gitignored — re-run the notebook to recreate them.
- The docstore (parent/child node relationships) is in-memory only in this notebook; it isn't persisted across kernel restarts.
